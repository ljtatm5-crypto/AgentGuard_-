# 审计 A：固定规则、证据与统计口径

审计时间：2026-10-25。审计范围：桌面 `/api/v2` 执行链、固定规则入口、持久化证据、修复前后指标；交叉只读检查 B 的安全判定桥与适配器。没有访问任何真实外部靶场。

## 发现与修复

1. **空规则可能绕过安全判定。** 原代码仅在 `rules` 非空时进入 B 引擎，显式空列表会退回泛化规则。已改为按字段是否存在分流：空规则或缺原始轨迹必须待复核，不能因回答含“知识库”而通过。
2. **复判会采用后来修改的用例。** 已在执行前深拷贝输入、步骤、禁止项、风险标签和判定配置，保存快照及 SHA-256 指纹。复判使用原快照，缺陷攻击链也使用当时的输入。没有快照的历史任务明确返回 `409 rule_snapshot_missing`，要求重新执行。
3. **不同实验可能被混为修复对照。** 配对键增加测试集版本和规则/输入指纹。仅对同测试集、同版本、同用例、同快照的本地校园模拟器 v1/v2 结果计算配对攻击成功率；无可比样本返回 `null`。

## 已验证的规则边界

- 通用引擎先执行确定性规则；已有确定结论时不调用 LLM 补充函数。
- 规则无法判定时，LLM 输出只作为带证据和置信度的建议；最终状态固定为待人工复核。
- B 引擎任一确定失败优先于人工复核标记和未知规则。桌面执行链没有调用 LLM，模板生成返回 `llm_used: false`。
- 原始轨迹持久化后可回指到具体运行与用例。复判不再次执行工具，也不重复创建轨迹或缺陷。
- 真实执行异常记录错误事件并置为待复核，不能成为通过。
- 原始样本仅创建资产与测试集，不预造执行结果或成功率；没有分母的比例为 `null`。

## 验证方式

使用独立内存 SQLite 数据库及本地虚拟校园靶场，不修改用户业务库。执行 `backend/.venv/Scripts/python.exe -m pytest tests/test_desktop_api.py tests/test_rule_engine.py -q`。

专项测试覆盖：完整 v1/v2 批量执行、任务汇总、轨迹回指、重复判定、模板来源、外部目标拒绝、空规则待复核、修改用例后的复判稳定性、不同版本/规则不配对、缺历史快照的显式错误。最终通过数以本次测试输出为准。

## 交叉审查与边界

已与 B 交换空规则分流、快照和配对方案，并请求复核其多轮证据及缺策略决策的写入规则；向 C 说明 `computed_from_run_ids` 是全部统计来源，不能用数组前两项冒充修复前后运行 ID，平均耗时为每条完成用例的平均值。

这些结果证明本地确定性模拟器上的工具链闭环，不能代表真实 Dify、大模型泛化能力或真实网站攻击效果。`risk_observed` 来自同一模拟器的可观察行为规则，风险检出率属于本地规则一致性指标，尚无独立人工金标数据集；不得宣传为独立评测准确率。快照冻结的是规则配置与输入，不是整个 Python 判定实现，因此跨代码版本复判仍应保存对应 Git 提交。
