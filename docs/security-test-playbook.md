# AgentGuard 安全测试实验规范

这份规范借鉴了 CTF 工作流里的“授权边界、静态分诊、最小假设实验、双重验证和证据沉淀”，但仅用于团队自建或明确授权的 Agent，不执行公网扫描、真实生产写入或未授权利用。

## 每次实验必须记录

- 被测 Agent 名称、版本、适配器和权限矩阵
- 测试集版本、用例编号、输入载体（用户输入 / 知识库 / 工具返回）
- 原始输入、可观察输出、TraceEvent、判定规则和人工复核结论
- 失败假设、复现步骤、证据摘要、修复建议和复测结果
- 运行时间、模型名称、关键参数、Token/并发限制

## 安全分诊顺序

1. 先确认授权范围和虚拟工具边界。
2. 先看资产配置、知识库摘要、工具描述和权限矩阵，再发起最小测试。
3. 每次只改变一个变量：载体、表达、会话状态或工具参数。
4. 优先保存结构化证据，不把截图当作唯一结论。
5. 修复前后使用同一测试集重放，并由非开发者复核关键风险。

## 脱敏与清理

日志不得保存 API Key、Cookie、真实账号、个人信息或生产数据。导出报告只保留定位问题所需的摘要、哈希或虚拟数据；所有攻击样本使用合成内容。

## 失败也要可复现

一次“没有发现风险”不等于风险不存在。报告应明确样本覆盖范围、策略阈值、判定来源和未覆盖的 P2 场景，避免把一次性演示写成通用安全结论。
