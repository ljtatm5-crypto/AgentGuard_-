# 审计 B：授权范围与出站边界

审计时间：2026-10-25。审计范围：`ScopeGuard`、旧 API 的 `validate_target_scope`、B 适配器远程分支及桌面 `/api/v2` 本地执行入口。只读检查现有实现，没有访问任何真实外部靶场。

> 后续更新：本项目已实现受控 Dify 适配器和本地假服务测试。公网限制不变，但“完全没有远程请求实现”的旧结论已过时。

## 结论

当前可执行路径采用默认拒绝。未授权域名在 DNS 查询前被拒绝；公网 IP、IPv4 映射 IPv6、公网黑名单和特殊地址不能借授权清单绕过；只有全部解析结果均属于回环或 RFC 1918/ULA 的授权域名才被放行。远程适配器在门禁之后立即返回 `NotImplementedError`，当前代码没有 HTTP 请求实现。

因此，没有发现当前版本可绕过范围门禁并向公网发请求的高风险路径。这个结论只适用于本地确定性靶场，不代表真实 Dify 适配器的网络隔离已经完成。

## 残余风险

1. **授权证据仍是调用方自报。** `authorization_confirmed=true` 加上任意非空授权编号即可通过 `validate_target_scope`；`AuthorizationRecord` 和 `record_authorization()` 没有接入校验流程，成功检查也不会自动写入记录。真实远程适配器启用前，应把授权目标、负责人、用途、证据编号和有效期保存为服务端记录，并校验目标、端口、Agent 与记录的绑定关系。
2. **DNS 检查和实际连接之间存在竞态窗口。** 当前实现先调用 `getaddrinfo` 判定地址，未来 HTTP 客户端通常会再次解析域名。启用远程适配器时应固定已验证的解析地址、禁用自动重定向，或由受控连接层复验每一跳，防止 DNS 重绑定和重定向越过边界。
3. **链路本地地址与注释不一致。** `scope.py` 的注释称允许链路本地地址，但实际只放行回环、RFC 1918 和 IPv6 ULA，`169.254.0.0/16` 与 `fe80::/10` 会拒绝。这是偏安全的文档不一致；如确有本地设备靶场需求，应先明确授权机制再开放。
4. **公开文档夸大了留痕。** `docs/security-agent.md` 写有“显式授权清单放行并留 AuthorizationRecord”，但当前实现只校验授权主机集合，不创建 `AuthorizationRecord`。在远程适配器完成前，应按实际行为描述。

## 已验证边界

- `file://`、缺失主机、账号密码、无效或零端口均拒绝。
- 未列入授权清单的域名不触发 DNS 查询或 HTTP 请求。
- 授权域名只要解析出任一非私网地址就整体拒绝。
- 公网 IP 即使进入授权清单也拒绝；常见公网域名黑名单不能由加白绕过。
- 回环、RFC 1918 私网与 IPv6 ULA 可由守卫识别；`0.0.0.0`、组播、保留地址拒绝。
- 旧 API 的远程调用路径同时经过 `ScopeGuard` 与显式主机白名单；桌面 `/api/v2` 仅注册和执行 `local://` 校园靶场。
