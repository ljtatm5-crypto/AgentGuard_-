# AgentGuard 工作区重构说明

本轮按照第二轮审核完成核心工作流重构，目标是让界面从“记录管理后台”转为“可操作的智能体测试工作台”。

## 已执行

- **Agent 资产**：多个 Agent 以紧凑资产卡片展示，选中后在下方独立详情中查看连接信息、知识库、工具权限和授权范围。
- **测试工作室**：AI 候选支持逐条选择、修改名称、输入、步骤、预期、禁止行为和风险等级，也支持新增、删除和人工确认保存。
- **Mock AI 演示**：Mock 模式可以展示完整候选审核流程，但始终标注“Mock 演示候选，未调用真实模型”。
- **执行工作区**：左侧筛选和选择用例，中间展示输入、检索、工具、策略、响应节点，右侧集中展示判定来源、置信度、理由和证据。
- **攻击链节点图**：实际事件使用实线，推断关系使用虚线；点击节点可查看对应证据并跳转到原始轨迹。
- **逐用例回归差异**：报告页可选择同测试集下两次运行，显示已修复、仍存在、新增回归和无法比较。
- **Clearflow 视觉**：使用通透玻璃面板、轻量点阵画布和分层阴影，保持单一蓝色强调色，并保留明暗主题及减少动态支持。
- **可读性**：正文提升到 15px 基础字号，关键说明为 14px，移动端增加底部导航安全距离。
- **性能**：页面改为路由级懒加载，生产主包降到约 424KB，消除 Vite 500KB 体积警告。

## 暂不执行

- **实时后台任务**：当前本地确定性靶场执行时间短，同步执行足够演示。改为任务队列、轮询或 SSE 会涉及执行器、状态机与现有回归测试，封版前引入风险较高。真实 Dify 长时间运行场景上线前必须补这一层。
- **PDF 报告**：当前 Markdown + CSV 已包含可复核数据。正式 PDF 排版可在提交材料定稿后单独制作。
- **强制 1 人审批**：Ruleset 目前要求 PR 和状态检查，但批准人数为 0。仓库尚未确认三名 GitHub 协作者均有审查权限，贸然开启会阻塞合并。

## 验证门槛

- 后端完整 pytest。
- 前端类型检查、ESLint、Mock 自检和生产构建。
- Mock 页面与流程 Playwright。
- 真实 API Playwright。
- GitHub Pages 子路径、深层路由、Mock API 和 Service Worker。
