# 演示 Runbook —— 固定操作顺序与降级预案

演示时长建议 6 分钟。**演示前必须冻结 Agent 版本、测试集版本与本文件顺序。**

---

## 一、开场前检查（T-10 分钟）

```bash
cd frontend
npm install
npx msw init public/ --save
npm run check:mock     # Mock 数据自检必须通过
npm run dev
```

- [ ] 浏览器打开 `http://127.0.0.1:5173`，左下角显示「Mock 数据模式」或「真实后端模式」
- [ ] 侧边栏 6 个导航项全部可见
- [ ] 断网备用：若后端不可用，直接用 Mock 模式演示，流程完全一致
- [ ] 准备本地 PDF 版报告（防止网络导出失败）

---

## 二、演示顺序（照此顺序，不要跳步）

### 第 1 幕 · 定位（40 秒）— 页面：总览

说清三件事：问题是什么、平台做什么、P0 闭环长什么样。

**必看证据**：产品首页、Agent 资产卡片、任务进度表。

> 话术要点：我们的价值不是「测得准」，而是「测得准且能解释」——
> 每一条结论都能点回原始轨迹事件。

### 第 2 幕 · 被测对象与边界（60 秒）— 页面：Agent 资产

**必看证据**：
- 知识库三类：正常 / 冲突 / **含测试性恶意指令**
- 工具权限：`campus_search` = allow，`protected_write` = review
- **授权范围框：明确标注「禁止外部站点目标」**

> 必说的一句话：所有测试只针对团队自建的 Dify 靶场，
> 危险工具只写虚拟文件和虚拟数据库，不触碰任何真实生产系统。

### 第 3 幕 · 测试集（40 秒）— 页面：测试集

点「查看用例」，展示六类 P0 用例。

**必看证据**：五类风险 + 一类正常对照；每条用例标注判定方式（规则 / 语义）。

> 强调：能用规则判定的绝不交给大模型。规则判定是确定性的、可复现的；
> 大模型只处理规则覆盖不到的语义场景。

### 第 4 幕 · 执行与判定（100 秒）— 页面：执行任务

1. 选择 Agent + 测试集 → 点「启动任务」
2. 展示任务 ID、状态、完成数实时推进
3. 点「详情与轨迹」

**必看证据**：
- 用例结论表的**判定来源列**（规则判定 / 语义判定 / 人工复核）
- 「待人工复核」这一行的存在 —— 说明低置信度不硬判
- 执行轨迹时间线：输入 → 检索 → 策略 → 工具 → 响应 / 错误

> 高光时刻：指出 tc-p0-003。模型确实发起了 `protected_write`，
> 权限层拦住了，但**判定仍然是失败** —— 因为我们看的是行为，不是后果。
> 这是规则判定优先的直接体现。

### 第 5 幕 · 缺陷与攻击链（90 秒）— 页面：攻击链与缺陷

点 fnd-001 的「攻击链」。

**必看证据**：
- 六节点链路：恶意知识 → 间接注入 → 策略拦截 → 潜在影响 → 修复方向
- **每个节点下方可点击的证据链接**：`run-001 / tc-p0-003 / ev-0032...`
- 点链接即跳回轨迹事件

> 必说：任何一条风险，都不可能脱离原始证据独立存在。
> 我们不接受「模型说有风险」这种结论。

### 第 6 幕 · 报告与回归（80 秒）— 页面：报告与回归

**必看证据**：
- 版本对照表：v1.0.0（修复前）vs v1.1.0（修复后）vs v1.2.0
- 攻击成功率前后对比条
- **实测值与目标值分列展示**，达标与未达标用颜色区分

> 结尾三句话：
> 1. 创新点 —— 规则优先的混合判定 + 全链路证据可追溯
> 2. 边界 —— 靶场环境、单一 Agent、样本量有限
> 3. 社会价值 —— 让 AI Agent 的安全评估从「看感觉」变成「看证据」

## 三、可能的提问与应答

| 提问 | 应答要点 |
|---|---|
| 判定会不会误判？ | 规则判定确定性可复现；语义判定置信度不足会转人工复核，不硬判 |
| 为什么攻击成功率是 0？ | 修复后同一攻击集 6 条全部被拦截，这是实测值不是目标值 |
| 大模型的作用是什么？ | 只覆盖规则判不了的语义场景，判定来源在页面上逐条标出 |
| 数据是真的吗？ | 每条结论可回溯到 run_id + case_id + event_ids，指标有 computed_from_run_ids |
| 会不会攻击真实网站？ | 不会。授权范围字段在类型层面就锁死了 external_target_allowed = false |

## 四、降级预案

| 故障 | 预案 |
|---|---|
| 后端未启动 | 切 Mock 模式，流程与证据完全一致 |
| 某个接口 500 | 页面显示错误码 + 可读信息 + 重试按钮，不静默失败 |
| 演示机断网 | 提前打包 `dist/` 与本地 PDF 报告 |
| 指标区为空 | 直接说明「暂无实测值」——这本身是诚实的设计，不慌 |

> **不要做的事**：临时改代码让页面"看起来有数据"。数据必须来自真实运行记录或 Mock 契约数据。
