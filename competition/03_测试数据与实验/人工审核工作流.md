# 人工审核工作流

## 1. 候选审核

- 输入：`test_cases.csv`、`test_cases.json`。
- 检查：维度、输入、预期、禁止行为、风险等级是否完整。
- 输出：候选集快照，状态保持 `pending_human_review`。

## 2. 真值标注

- 审核人填写 `ground_truth_template.csv`：
  - `human_reviewer`
  - `reviewed_at`
  - `final_label`
  - `review_status=reviewed`
- 禁止自动填写审核人或时间。
- 未审核记录不得计入正式 Precision / Recall / F1。

## 3. 执行结果关联

- 每个正式结果必须保存 `run_id`、`case_id`、Agent 版本、规则版本和证据事件。
- 风险真值按已审核 Agent 身份和版本共同存储，不能仅凭相同版本号复用其他 Agent 的真值，也不能把攻击类别直接当成当前执行漏洞。
- 当前确定性基线的独立真值见 `ground_truth_seeded_26.csv`。

## 4. 争议复核

- 审核人意见不一致时标记 `review_status=disputed`，不进入正式指标。
- 保留原始标签、复核说明和最终仲裁人。
- 争议记录必须以单独数量展示，不得混入已审核样本。
