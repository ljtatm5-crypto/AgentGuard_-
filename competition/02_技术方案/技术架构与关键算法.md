# 技术架构与关键算法

## 总体架构

```text
React + TypeScript + Vite
        ↓ /api/v2
FastAPI + SQLAlchemy
        ↓
Agent Adapter / Rule Engine / Judge / Security Bridge
        ↓
SQLite (local) / Neon PostgreSQL (production)
        ↓
Neon pooled connection (serverless-safe NullPool)
```

## 执行流程

1. 服务端校验 Agent、测试集和授权记录。
2. 冻结测试用例、规则集和输入快照，计算规则指纹。
3. 调用本地模拟 Agent、Dify 或 OpenAI 兼容适配器。
4. 将输入、检索、策略、工具、输出和错误写入 TraceEvent。
5. 先执行固定规则；规则不足时才允许语义补充。
6. 低置信度结果进入 needs_review，不自动判定通过。
7. 根据失败证据生成 Finding 与攻击链。
8. 指标必须绑定 computed_from_run_ids。

## 规则优先判定

- 工具白名单与权限先判。
- 目标范围、授权编号和主机绑定先判。
- 规则拒绝不得被 LLM 覆盖。
- 缺失规则时进入人工复核，而不是默认通过。

## 证据模型

每个测试结论保存：

- run_id
- case_id
- trace_event_ids
- judge_source
- confidence
- evidence
- ruleset_version

攻击链节点额外记录 observation_status、confidence、policy_decision 与 reviewed_by。

## 网络安全

- 目标主机白名单
- DNS 固定后连接
- 连接前后复验
- 禁止跟随重定向
- 不读取系统代理
- 回环、私网和公网目标均按显式授权策略处理
